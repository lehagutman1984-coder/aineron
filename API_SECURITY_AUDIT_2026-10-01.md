### 2. [ИСПРАВЛЕНО 2026-10-01, коммит 2c5210f] Захват чужого аккаунта перебором кода подтверждения email — анонимно, без rate-limit

**Статус: закрыто.** `verify_email_token()` (GET-ссылка) теперь матчит только длинный токен, код-фоллбэк убран. `ajax_verify_email_code` матчит код строго на `request.user`. `ajax_password_reset` — generic-ответ + rate-limit (1/email/10мин, 5/IP/час). 10 regression-тестов (`users/tests_email_verification_security.py`), включая прямую проверку "чужим кодом нельзя войти в чужой аккаунт" — зелёные на обоих инстансах.

- `GET /users/api/verify-email/<code>/` (`users/views.py:330` `verify_email()`,
  без `@login_required`) → `verify_email_token()` (`users/email_service.py:338-347`)
  при промахе по длинному токену **падает на поиск по 6-значному коду**:
  `CustomUser.objects.get(email_verification_code=token)`. При совпадении —
  `login(request, user, ...)` без проверки, кто спрашивал.
- Нигде по цепочке (`users/urls_api.py`, Django view, nginx.conf) **нет rate-limit**
  — ни `django-ratelimit`, ни DRF throttle (это legacy Django view, не DRF), ни
  `limit_req` в nginx (проверено — зоны лимитов в nginx.conf отсутствуют вовсе).
- Пространство кода — `10^6`, генерируется `random` (не `secrets`), без TTL.
  При ~100 неподтверждённых аккаунтов (оценка из памяти проекта) один хит —
  это порядка 10^4 анонимных GET-запросов без каких-либо ограничений.
  При попадании — чужая сессия, чужие чаты/файлы/баланс, и можно сразу выпускать
  API-ключи (email стал "подтверждён").
- POST-вариант (`/users/api/ajax/verify-email/`, `ajax_verify_email_code`,
  `users/views.py:348`) — та же уязвимость, но требует `@login_required` (чуть уже).
- Соседний баг той же природы: `POST /users/api/ajax/password-reset/`
  (`users/views.py:251`) меняет пароль **сразу**, без подтверждения по ссылке,
  шлёт новый пароль в письме открытым текстом, без rate-limit — позволяет
  анонимно и многократно "взрывать" пароль любого юзера по email (DoS аккаунта).
- На `.net` риск ниже: `email_verified=True` ставится сразу при `INTL_MODE`, код
  вообще не выдаётся.

**Фикс** (минимально инвазивный, не трогает фронт): искать код **в паре с текущим
залогиненным/сессионным пользователем**, а не по всей таблице; TTL + счётчик
попыток с блокировкой; генерировать код через `secrets`; добавить rate-limit
(хотя бы `django-ratelimit` по IP+email) на оба эндпоинта верификации и на
password-reset; убрать code-fallback из GET-пути вообще (ссылка должна пускать
только по длинному токену).

## Документация `/api-docs/` — отдельный разрез (не безопасность, а "работает ли по инструкции")

Полный разбор — см. отчёт агента (doc-parity) в истории диалога. Коротко:
примеры для Anthropic SDK, TTS (`tts-1`), "видео через images/generations" и
"баланс через `/usage/`" в документации **не работают** при буквальном
копировании. Управление ключами (`scopes`, лимит 10, формат ответа) и полный
контракт вебхуков (подпись, события, которые реально отправляются) не описаны
вовсе. Три несогласованных источника "официального" контракта: кастомная
`/api-docs/`, автогенерируемый Swagger (`/v1/docs/`, видит вообще все эндпоинты)
и устаревший Postman.

## Расширение аудита на фронтенд (2026-10-02)

По просьбе пользователя охват расширен на `frontend/` — тремя параллельными
агентами: (а) общая безопасность/конфиг фронта, (б) дрейф фронта от
сегодняшних бэкенд-изменений (контракт API), (в) полнота i18n на .net.
Найдено и исправлено:

- **Iframe-песочница ArtifactPanel эффективно отключена** — `sandbox="allow-scripts allow-same-origin"`
  вместе с `blob:`-URL (наследует origin создавшего документа) снимал изоляцию
  целиком: сгенерённый LLM HTML/JS получал доступ к `parent.document`,
  `localStorage`, авторизованным fetch-запросам. Убран `allow-same-origin`.
- **5 мест `dangerouslySetInnerHTML` без санитизации** (chat/[chatId], compare,
  ResearchReport×2, ResponseVariants) — обёрнуты в новый `lib/sanitize.ts`
  (`isomorphic-dompurify`, работает и в серверном рендере App Router).
- **Open redirect / DOM-XSS через `?next=`** на login/register — добавлен
  `safeNextPath()` в `lib/utils.ts` (только относительные пути, без `//`).
- **Next.js-страницы не отдавали security-заголовков** — HSTS, X-Frame-Options,
  X-Content-Type-Options, Referrer-Policy добавлены на уровне nginx-сервера
  (оба `nginx.conf`/`nginx.intl.conf`). CSP намеренно не включён — инлайн-скрипты
  темы и Метрики требуют отдельного захода через report-only.
- **CORS** — localhost-origins в `CORS_ALLOWED_ORIGINS` убраны из прод-конфига,
  спрятаны за `if DEBUG`.
- **Locale-prefix баг** — `email_not_verified` редирект на `/verify-email/`
  был хардкодной (без префикса локали), ломался для non-default-locale
  пользователей .net (`as-needed`-роутинг next-intl). Исправлено.
- **Две реальные live-регрессии от сегодняшних же бэкенд-фиксов**, пойманы
  агентом (б) ДО того, как успели повредить продакшн надолго:
